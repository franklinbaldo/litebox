# ARM64/aarch64 Port Implementation Plan

> **For Claude:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task.

**Goal:** Port `litebox_runner_linux_userland` and all its dependencies to ARM64/aarch64, using the rewriter-based syscall interception approach only.

**Architecture:** ARM64 uses `SVC #0` (4 bytes) for syscalls and `TPIDR_EL0` for TLS. Unlike x86_64's dual FS/GS TLS registers, ARM64 has a single shared TLS register, requiring a per-thread host TLS lookup table in the trampoline. The trampoline must also intercept `MSR TPIDR_EL0, Xn` instructions and provide a sigreturn trampoline (glibc doesn't set `SA_RESTORER` on ARM64). Signal handler TLS recovery uses power-of-2 aligned alt-stacks.

**Tech Stack:** Rust (no_std for shim/common), ARM64 assembly (inline asm), C (rtld_audit), ELF manipulation.

**Key reference docs:** The previous ARM64 port at `https://github.com/sangho2/litebox/tree/arm64/docs` — three markdown files covering rewriter development, runner status, and architecture comparison.

## Phase 2: Syscall Rewriter (litebox_syscall_rewriter)

### Task 7: Create the ARM64 syscall rewriter

**Files:**
- Create: `litebox_syscall_rewriter/src/arm64.rs` (new module, ~800-1200 lines)
- Modify: `litebox_syscall_rewriter/src/lib.rs` (add `mod arm64` and dispatch)
- Modify: `litebox_syscall_rewriter/src/main.rs` (if arch dispatch needed)

This is the largest single task. The ARM64 rewriter must:

1. **Scan ELF** for `SVC #0` instructions (opcode `0xD4000001`, 4 bytes) and `MSR TPIDR_EL0, Xn` instructions (pattern: `(insn & 0xFFFFFFE0) == 0xD51BD040`).

2. **Generate per-instruction trampolines**:
   - For each `SVC #0`: Replace with `B <trampoline_offset>` (direct branch, ±128MB range). For far jumps (>128MB): use `ADRP + ADD + BR` (12 bytes) — needs to borrow adjacent instructions.
   - For each `MSR TPIDR_EL0, Xn`: Replace with branch to a trampoline that updates the TLS lookup table.

3. **Trampoline layout** (adapted to new header-at-end format):
   ```
   [original ELF][padding to 0x1000][trampoline code][TrampolineHeader64 at end]
   ```
   
   Trampoline code layout:
   ```
   Offset 0: syscall_callback address (8 bytes, initially 0, filled at runtime)
   Offset 8: TLS lookup table pointer (8 bytes, initially 0, filled at runtime)
   Offset 16: Sigreturn trampoline (~16 bytes: MOV x8, #__NR_rt_sigreturn; SVC #0; padding)
   Offset 32+: TLS lookup table (256 entries × 16 bytes = 4096 bytes)
   Offset 4128+: Per-SVC/MSR trampoline snippets
   ```
   
   **Per-SVC trampoline snippet** (~40 bytes):
   ```asm
   SUB SP, SP, #32          // save space for x16, x17, x30
   STP x16, x17, [SP]       // save x16, x17
   STR x30, [SP, #16]       // save x30 (link register)
   MRS x16, TPIDR_EL0       // get guest TLS
   // TLS table lookup to find host TLS for this thread
   ADRP x17, <tls_table>    // load TLS table base
   ADD x17, x17, <tls_table_lo>
   // ... lookup sequence (hash TPIDR_EL0 to find host TLS entry)
   LDR x18, [x17, ...]      // x18 = host TLS pointer
   // Set return address
   ADRP x30, <return_addr>
   ADD x30, x30, <return_lo>  // or: ADR x30, <return_addr> if close enough
   // Jump to handler
   ADRP x16, <handler>
   ADD x16, x16, <handler_lo>
   LDR x16, [x16]           // load handler address from trampoline offset 0
   BR x16
   ```
   
   The exact snippet will be refined during implementation. Refer to the old port's trampoline design in `ARM64_REWRITER_DEVELOPMENT.md`.

4. **Key differences from old port:**
   - TrampolineHeader64 is at the **end** of the file, not beginning of trampoline section
   - Entry point (syscall_callback address) is at trampoline code offset 0 (first 8 bytes)
   - TLS table pointer at offset 8 (second 8 bytes)

**Step 1: Create `arm64.rs` with the scanner**

Implement `scan_elf_arm64()` that finds all SVC #0 and MSR TPIDR_EL0 instructions in executable segments. Return a list of `(offset, InstructionType)` where `InstructionType` is `Svc` or `MsrTpidr { reg: u8 }`.

**Step 2: Implement trampoline generation**

Implement `rewrite_arm64()` that:
- Calls the scanner
- Computes trampoline vaddr (page-aligned above highest PT_LOAD)
- Generates per-instruction trampoline snippets
- Patches original instructions with branches
- Writes trampoline code + TrampolineHeader64 at end

**Step 3: Integrate with lib.rs**

Add `#[cfg(target_arch = "aarch64")] mod arm64;` and dispatch from the main rewrite function.

**Step 4: Verify it compiles**

Run: `cargo check -p litebox_syscall_rewriter --target aarch64-unknown-linux-gnu`

**Step 5: Commit**

```
feat(rewriter): add aarch64 syscall rewriter (SVC + MSR TPIDR_EL0 interception)
```

## Phase 3: Platform Layer (litebox_platform_linux_userland)

### Task 8: Add aarch64 platform assembly (syscall_callback + switch_to_guest)

**Files:**
- Modify: `litebox_platform_linux_userland/src/lib.rs` (add aarch64 assembly alongside x86_64)
- Modify: `litebox_platform_linux_userland/Cargo.toml` (if new deps needed)

This is the second-largest task. The platform layer needs:

1. **Thread-local storage**: Since ARM64 has only `TPIDR_EL0` (shared with guest), we need a different approach from x86_64's dual FS/GS:
   - Save host `TPIDR_EL0` in the TLS lookup table before entering guest
   - On syscall entry, the trampoline has already looked up host TLS and put it in `x18`
   - Use `x18` as the "host TLS base" throughout the callback

2. **`.tbss` thread-local variables** (same concept as x86_64):
   - `scratch: usize` — temporary storage
   - `host_sp: usize` — saved host stack pointer  
   - `host_bp: usize` — saved host frame pointer (not needed on ARM64, but keep for symmetry)
   - `guest_context_top: usize` — pointer to top of PtRegs on host stack
   - `guest_tpidr: usize` — saved guest TPIDR_EL0
   - `in_guest: u8` — flag for signal handler detection
   - `interrupt: u8` — interrupt pending flag

3. **`syscall_callback`** (naked fn, ARM64 assembly):
   ```asm
   // Entered from trampoline with:
   //   x18 = host TLS pointer (from trampoline's TLS table lookup)
   //   x30 = return address in guest code
   //   x16, x17, x30 saved on guest stack at [SP], [SP+8], [SP+16]
   //   SP adjusted by -32 by trampoline
   
   // Clear in_guest flag
   // Restore host TPIDR_EL0 from x18
   MSR TPIDR_EL0, x18
   
   // Save all guest registers into PtRegs on host stack
   // Switch to host stack (load from TLS)
   // Recover x16, x17, x30 from guest stack frame
   // Call into Rust syscall dispatch
   ```

4. **`switch_to_guest`** (naked fn, ARM64 assembly):
   ```asm
   // Set in_guest flag
   // Check interrupt flag — if set, return early
   // Restore all guest registers from PtRegs
   // MSR TPIDR_EL0, <guest_tpidr>
   // BR x18  (guest PC, loaded into x18 before jump)
   ```

5. **Signal handling**:
   - Signal handlers need to detect if signal interrupted guest code
   - ARM64 approach: power-of-2 aligned alt-stacks with host TLS at `aligned_base + ALT_STACK_ALLOC_SIZE - 8`
   - Recovery: `SP & ~(ALT_STACK_ALLOC_SIZE - 1)` gives aligned base, then read host TLS from known offset
   - No `rdgsbase` equivalent — this IS the recovery mechanism on ARM64

6. **Cfg guard**: Update the module-level cfg:
   ```rust
   #![cfg(all(target_os = "linux", any(target_arch = "x86_64", target_arch = "x86", target_arch = "aarch64")))]
   ```

**Step 1: Update cfg guard and add aarch64 TLS module**

**Step 2: Implement `syscall_callback` in ARM64 assembly**

**Step 3: Implement `switch_to_guest` in ARM64 assembly**

**Step 4: Implement signal handler TLS recovery for ARM64**

**Step 5: Verify it compiles**

Run: `cargo check -p litebox_platform_linux_userland --target aarch64-unknown-linux-gnu`

## Appendix: Key Constants and Values for ARM64

| Item | ARM64 Value | x86_64 Value |
|------|-------------|--------------|
| Syscall instruction | `SVC #0` (0xD4000001, 4 bytes) | `SYSCALL` (0x0F05, 2 bytes) |
| Syscall number register | x8 | RAX |
| Syscall args | x0-x5 | RDI, RSI, RDX, R10, R8, R9 |
| Syscall return | x0 | RAX |
| TLS register | TPIDR_EL0 (single, shared) | FS + GS (dual) |
| MSR TPIDR_EL0 pattern | `(insn & 0xFFFFFFE0) == 0xD51BD040` | N/A |
| MRS TPIDR_EL0 pattern | `(insn & 0xFFFFFFE0) == 0xD53BD040` | N/A |
