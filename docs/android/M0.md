# Android userspace M0 — bionic ELF probe

Parent: #25

This milestone proves or falsifies the narrowest useful Android-on-LiteBox claim: an x86_64 ELF genuinely linked against Android bionic can execute through the existing Windows-userland Linux shim without WSL, Hyper-V, QEMU, a kernel driver, or administrator privileges.

## Contract

The probe rootfs is a TAR containing only the Android executable, Android `linker64`, bionic `libc.so`, and the transitive runtime files required by that executable. Guest ELFs must pass through the same LiteBox rewrite/package path used by other Linux workloads.

Expected invocation:

```powershell
litebox run .\android-m0.tar /system/bin/litebox-android-hello
```

Expected stdout:

```text
hello from Android userspace on LiteBox
```

Expected exit code: `0`.

## Evidence gate

A successful report MUST record:

- Windows architecture and LiteBox commit
- SHA-256 of the input Android ELF and final TAR
- ELF interpreter (`/system/bin/linker64` or equivalent Android path)
- dynamic dependencies proving bionic rather than glibc/musl
- exact rewrite/package commands
- stdout, stderr, exit code
- repeated-run result

A failure MUST name the first unsupported assumption observed (loader, TLS, memory mapping, signal, syscall, filesystem layout, or packaging) instead of hiding it behind an Android-specific compatibility layer.

## Build fixture

The fixture source intentionally uses only libc-level behavior:

```c
#include <stdio.h>

int main(void) {
    puts("hello from Android userspace on LiteBox");
    return 0;
}
```

Build it with an Android NDK/AOSP x86_64 target. Do not substitute a Linux glibc or musl binary.

## Negative control

The same packaging harness must reject a fixture whose ELF interpreter/dependency evidence does not identify Android/bionic. This prevents a green test that accidentally exercised an ordinary Linux binary.

## Stop condition

Do not add Binder, Android properties, zygote, ART, graphics, or host capabilities in M0. If the bionic ELF cannot execute, keep the failing fixture as a compatibility regression test and document the boundary before advancing.
