# M4 — Android compatibility substrate

Parent RFC: #25. Stacked on M3 / PR #29.

## Goal

Turn the current Android experiment into a measurable x86_64 Android userspace compatibility profile before introducing Binder or framework lifecycle work.

This milestone is complete only when failures can be attributed to an explicit unsupported capability rather than accidental gaps in basic Linux/bionic behavior.

## Hard gate

The minimal bionic reproducer from #30 is the first gate:

```text
toybox echo hello -> Android linker64 -> LiteBox -> Windows
```

Expected result: stdout contains `hello` and the process exits 0. A dynamically linked glibc fixture remains a control.

## Compatibility matrix

Every semantic below must have a small fixture before a large APK is allowed to depend on it:

- memory: mmap, MAP_FIXED, mprotect, munmap, mremap, madvise, file-backed executable mappings;
- threads: clone, futex, robust lists, TID lifecycle, scheduler queries;
- signals: masks, altstack, delivery and restart behavior;
- eventing: epoll, eventfd, timerfd, poll/select;
- filesystem: openat/stat/readlink, symlinks and Android rootfs permissions;
- sockets: Unix-domain sockets plus bounded TCP/UDP host capability paths;
- process ABI: prctl and bionic/ART process assumptions;
- clocks, randomness and auxv;
- `/proc` views consumed by Android userspace.

## Design rule

Improve the generic Linux shim where the behavior is Linux ABI. Add Android-specific code only for Android-specific kernel/device contracts. Unknown operations must fail deterministically.

## Acceptance

- [ ] #30 reproducer is green and covered in CI
- [ ] syscall-free executable mappings are observably neutral under runtime rewriting
- [ ] MAP_FIXED behavior is regression-tested
- [ ] each matrix category has at least one positive fixture and one unsupported/negative case where meaningful
- [ ] failures identify the missing semantic instead of collapsing to exit 139
- [ ] no Binder, zygote, system_server or graphics dependency is required to pass M4
