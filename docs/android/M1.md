# Android userspace M1 — bounded runtime bundle

Parent: #25. Stacked on M0.

M1 turns the one-off bionic fixture into a reproducible Android userspace bundle without silently importing a whole system image.

`build_runtime_bundle.py` accepts an extracted x86_64 Android/AOSP tree, one or more explicit guest entry paths, and computes the ELF `DT_NEEDED` closure through a bounded list of Android library directories. Missing or ambiguous SONAME resolution fails closed.

Example:

```powershell
python scripts/android/build_runtime_bundle.py `
  --android-root C:\aosp-root `
  --entry /system/bin/toybox `
  --extra /system/bin/linker64 `
  --output .\android-runtime.tar
```

The resulting TAR is still an input to the existing LiteBox runner. This milestone does not add host mounts, overlays, Binder, ART, or an Android boot sequence.

## Acceptance

- [ ] every included path is printed
- [ ] dependency resolution is deterministic
- [ ] missing dependency fails
- [ ] ambiguous duplicate SONAME fails instead of guessing
- [ ] no path outside the supplied Android root is copied
- [ ] the bundle can run at least one selected Android base utility after LiteBox rewriting/package preparation
