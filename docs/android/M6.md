# M6 — Binder in LiteBox userland

Parent RFC: #25. Stacked on M5 / PR #32.

## Goal

Implement the Android Binder kernel/device contract inside LiteBox userland so real Android processes can communicate without a Windows kernel driver, VM, service installation, or administrator privilege.

## Guest contract

Expose the pinned Android release's Binder device surface through `litebox_shim_linux`:

```text
open/mmap/ioctl(/dev/binder)
  -> Linux shim
  -> LiteBox Binder backend
```

The backend owns bounded guest-only state:

- Binder processes and threads;
- nodes, handles and references;
- transaction and reply queues;
- shared transaction buffers;
- death notifications;
- context-manager/service-manager registration;
- deterministic lifecycle/cleanup.

Unknown Binder commands and malformed buffers fail closed. No arbitrary host IOCTL forwarding exists.

## Development order

1. fixture-level codec/validation for Binder command streams;
2. two synthetic native guest processes perform request/reply;
3. handle/reference lifecycle and death notification tests;
4. run the real AOSP `servicemanager` from the pinned image;
5. register and resolve a synthetic service through the real servicemanager.

## Isolation rule

Binder memory belongs to the guest model. Every offset, size and object descriptor received from guest memory is bounds-checked before host access. Resource counts and queued bytes are bounded.

## Acceptance

- [ ] `/dev/binder` open/mmap/ioctl path is implemented without host driver passthrough
- [ ] two guest processes complete deterministic request/reply
- [ ] malformed transaction buffers are rejected without host crash
- [ ] handle/node/ref cleanup is covered by tests
- [ ] real AOSP `servicemanager` starts
- [ ] a synthetic service can be registered and looked up through servicemanager
- [ ] no zygote, system_server or graphics dependency is required to pass M6
