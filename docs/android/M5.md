# M5 — Android runtime closure and process environment

Parent RFC: #25. Stacked on M4 / PR #31.

## Goal

Make the Android runtime bundle and guest process environment complete enough that native, ART and JNI workloads do not fail because a runtime-loaded file or basic Android process primitive is accidentally absent.

## Runtime closure

`DT_NEEDED` is necessary but not sufficient. The bundle builder must also model dynamic runtime loads for the pinned Android image, including ART/JNI components such as `libart`, `libjavacore`, `libopenjdk`, `libsigchain` and any additional libraries proven necessary by trace/evidence.

The bundle manifest must explain why every included file is present: entrypoint, ELF dependency, runtime/dlopen rule, framework asset, OAT/boot image, ICU/property data, or explicit fixture.

## Process environment

Provide the Android-facing environment required before Binder/framework startup:

- property area / property service semantics;
- required `/proc`, `/dev` and pseudo-files;
- ashmem/memfd/shared-memory behavior appropriate to the pinned release;
- Unix sockets used by Android daemons;
- logging path (`logd` compatibility or a narrow LiteBox adapter);
- Android UID/GID/credential semantics only within the guest model;
- deterministic filesystem layout, symlinks and modes.

## Design rule

Do not copy an uncontrolled full system image just to hide missing dependencies. Keep the bundle bounded and explainable. Prefer real Android userspace components and narrow LiteBox adapters at kernel/hardware boundaries.

## Acceptance

- [ ] bundle includes dynamic `dlopen` closure needed by ART/JNI
- [ ] manifest records provenance/reason for every bundled path
- [ ] DEX/JAR main runs without missing-file failures
- [ ] JNI loads a native `.so` dynamically and completes a round trip
- [ ] properties/shared-memory/logging fixtures pass
- [ ] missing optional hardware capabilities fail with an explicit unsupported result
- [ ] no Binder or graphics implementation is required to pass M5
