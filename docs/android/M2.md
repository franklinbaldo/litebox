# Android userspace M2 — ART / DEX smoke

Parent: #25. Stacked on M1.

M2 proves ART separately from APK packaging and Android framework lifecycle. The fixture is a Java `main()` compiled to a dex-containing JAR with Android `d8`, injected into the bounded Android runtime TAR, and executed with `dalvikvm64` (or another explicit ART entrypoint).

Expected output:

```text
hello from ART on LiteBox
```

## Fixture preparation

Compile `fixtures/android/ArtHello.java` with a local JDK, then run Android Build Tools `d8` to produce a dex-containing JAR. Pass that artifact to:

```powershell
python scripts/android/prepare_art_probe.py `
  --runtime-tar .\android-art-runtime.tar `
  --artifact .\art-probe.jar `
  --output .\android-art-probe.tar
```

Run:

```powershell
powershell -File scripts/android/run_art_probe.ps1 `
  -Tar .\android-art-probe.tar
```

The runtime TAR must already include the selected ART entrypoint and its dependency closure via M1.

## Acceptance

- [ ] fixture is compiled to DEX by Android `d8`
- [ ] ART entrypoint is an Android x86_64 binary from the supplied AOSP/runtime tree
- [ ] output is deterministic and exit code is zero
- [ ] no Binder, zygote, system_server, graphics, package manager, or host kernel Android component is required
- [ ] failures identify whether the boundary is ART startup, runtime library loading, memory/syscall compatibility, or fixture packaging

M2 is deliberately not an Android app lifecycle test. It isolates the VM/runtime prerequisite that APK testing depends on.
